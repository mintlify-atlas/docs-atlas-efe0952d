Aggregate gap analysis is the engine that makes shared discovery possible. Before asking you a single question, the skill reads every job description you provided, matches each requirement against your resume library, and builds a unified map of what is missing — collapsing identical gaps from multiple jobs into one entry instead of surfacing them separately per role. By the time Phase 2 begins, you have a prioritized list of unique gaps rather than a duplicated pile, and the skill can run one focused conversation that addresses all of them at once.

## What aggregate gap analysis does

The process runs in four steps, all automatically, before any user checkpoint.

**1. Extract requirements from all JDs.**
The skill performs a lightweight parse of each job description — enough to identify required skills, preferred technologies, and domain areas — without running the full per-job company research that happens later in Phase 3. This keeps Phase 1 fast.

```text
Job 1 (Microsoft 1ES):  Kubernetes, CI/CD, cross-functional leadership, Azure
Job 2 (Google Cloud):   Kubernetes, GCP, distributed systems, team management
Job 3 (AWS):            Container orchestration, AWS services, program management
```

**2. Match each requirement against your resume library.**
For every requirement across all jobs, the skill searches your library using the same confidence-scored matching strategies as single-job mode — direct match (40%), transferable (30%), adjacent (20%), and impact (10%).

**3. Flag gaps where confidence is below 60%.**
Any requirement where the best available match scores below the 60% confidence threshold is flagged as a gap. Matches above 60% are considered covered and do not appear in the discovery session.

**4. Deduplicate gaps across jobs.**
"Kubernetes at scale" appearing in all three job descriptions becomes a single gap entry, not three separate questions. The same applies to partial overlaps — "CI/CD pipeline management" in Jobs 1 and 2 merges into one important gap rather than consuming time in two separate discovery sessions.

## Gap prioritization

After deduplication, each gap is assigned a priority level based on how many jobs it affects:

| Priority level | Criteria | Discovery time |
|---|---|---|
| **Critical** (priority 3) | Appears in 3 or more jobs | 5–7 minutes each |
| **Important** (priority 2) | Appears in exactly 2 jobs | 3–5 minutes each |
| **Job-specific** (priority 1) | Appears in 1 job only | 2–3 minutes each |

Critical gaps are addressed first in Phase 2, because resolving them improves coverage across the most applications simultaneously.

## The gap analysis report

When Phase 1 completes, the skill generates `_aggregate_gaps.md` in your batch directory and presents a summary to you. The report includes:

- **Coverage summary per job** — how much of each job description is already matched by your existing library
- **Critical gaps section** — each gap with its current best match and confidence score
- **Important gaps section** — two-job gaps with the same detail
- **Job-specific gaps section** — single-job gaps that may still be worth addressing
- **Aggregate statistics** — total gaps found before deduplication, unique gaps after
- **Recommended discovery time estimate** — broken down by priority tier

- **Appears in:** Jobs 1, 2, 3
- **Current best match:** 58% confidence

## After gap analysis

Once the report is ready, the skill presents the summary and waits for your input at a checkpoint before proceeding:

```text
"Would you like to:
1. START DISCOVERY - Address gaps through conversational discovery
2. SKIP DISCOVERY - Proceed with current library (not recommended)
3. REVIEW GAPS - See detailed gap analysis first

Recommendation: Option 1 or 3 (review then start)"
```

- **Start Discovery** — moves directly to Phase 2 with the prioritized gap list
- **Skip Discovery** — proceeds to per-job processing using only your existing library; coverage will be lower for gapped requirements
- **Review Gaps** — displays the full `_aggregate_gaps.md` report so you can read through every gap before committing to the discovery session

<Tip>
Choose **Review Gaps** before starting discovery if this is your first batch or if the roles are especially important. Scanning the report in advance tells you exactly what experiences to think about during the branching interview — you will be better prepared to answer questions about Kubernetes if you have already reminded yourself of every container-related project you have worked on.
</Tip>
