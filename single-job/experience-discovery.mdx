Your resume library represents the experiences you've already written down. But the work you've done is almost certainly richer than what's been documented — side projects, volunteer roles, graduate research, recent initiatives, informal leadership, and contributions that felt too small to formalize but would speak directly to a hiring team. Phase 2.5 exists to surface that undocumented material through a structured but genuinely conversational interview. It doesn't ask static questions from a fixed list. It listens to what you say and decides what to ask next.

## How branching discovery works

Experience Discovery is **not a static questionnaire**. The skill identifies the gaps between what the template requires (based on the Success Profile) and what your library currently covers, then opens a conversation targeting each gap. The direction the conversation takes depends entirely on how you respond.

Each answer is classified into one of five branches, and the next question is chosen accordingly:

| Branch | When it triggers | What happens next |
|---|---|---|
| **YES (Direct)** | You have direct experience with the skill | Deep dive: scale, challenges, specific outcomes, metrics |
| **INDIRECT** | You worked adjacent to the skill or in a supporting role | Explore your specific role and what transferred |
| **ADJACENT** | You have related tools, methods, or domain experience | Assess whether it's close enough to mention |
| **PERSONAL/LEARNING** | You have personal projects, courses, or self-study | Evaluate recency and substance |
| **COMPLETE NO** | No experience in this area at all | Try a broader category, then move on gracefully |

## Discovery patterns covered

The skill uses three core discovery patterns depending on the type of gap being addressed.

### Technical Skill Gap Pattern

Used when the Success Profile identifies a specific technical skill or technology that your library doesn't cover.

```
INITIAL PROBE:
"I noticed the job requires {SKILL}. Have you worked with {SKILL} or {RELATED_AREA}?"

BRANCH A - If YES (Direct Experience):
  → "Tell me more - what did you use it for?"
  → "What scale? {Relevant metric}?"
  → "Was this production or development/testing?"
  → "What specific challenges did you solve?"
  → "Any metrics on {performance/reliability/cost}?"
  → CAPTURE: Build detailed bullet

BRANCH B - If INDIRECT:
  → "What was your role in relation to the {SKILL} work?"
  → "Did you {action1}, {action2}, or {action3}?"
  → "What did you learn about {SKILL}?"
  → ASSESS: Transferable experience?
  → CAPTURE: Frame as support/enabling role if substantial

BRANCH C - If ADJACENT:
  → "Tell me about your {ADJACENT_TECH} experience"
  → "Did you do {relevant_activity}?"
  → ASSESS: Close enough to mention?
  → CAPTURE: Frame as related expertise

BRANCH D - If PERSONAL/LEARNING:
  → "Any personal projects, courses, or self-learning?"
  → "What did you build or deploy?"
  → "How recent was this?"
  → ASSESS: Strong enough if recent and substantive
  → CAPTURE: Consider if gap critical

BRANCH E - If COMPLETE NO:
  → "Any other {broader_category} work?"
  → If yes: Explore that
  → If no: Move to next gap
```

### Soft Skill / Experience Gap Pattern

Used when the gap is a demonstrated capability — leadership, stakeholder management, cross-functional coordination — rather than a specific technology.

```
INITIAL PROBE:
"The role emphasizes {SOFT_SKILL}. Tell me about times you've {demonstrated_that_skill}."

BRANCH A - If STRONG EXAMPLE:
  → "What {entities} were involved?"
  → "What was the challenge?"
  → "How did you {drive_outcome}?"
  → "What was the result? Metrics?"
  → "Any {obstacle} you had to navigate?"
  → CAPTURE: Detailed bullet with impact

BRANCH B - If VAGUE/UNCERTAIN:
  → "Let me ask differently - have you ever {reframed_question}?"
  → "What was that situation?"
  → "How many {stakeholders}?"
  → "What made it challenging?"
  → CAPTURE: Help articulate clearly

BRANCH C - If PROJECT-SPECIFIC:
  → "Tell me more about that project"
  → "What was your role vs. others?"
  → "Who did you coordinate with?"
  → "How did you ensure alignment?"
  → ASSESS: Enough depth?
  → CAPTURE: Frame as leadership if substantial

BRANCH D - If VOLUNTEER/SIDE WORK:
  → "Interesting - tell me more"
  → "What was scope and timeline?"
  → "What skills relate to this job?"
  → "Measurable outcomes?"
  → ASSESS: Relevant enough?
  → CAPTURE: Include if demonstrates capability
```

### Recent Work Probe Pattern

Used to surface anything you've done in the last six months that hasn't made it into your resumes yet — the most common source of high-value undocumented experience.

```
INITIAL PROBE:
"What have you been working on in the last 6 months that isn't in your resumes yet?"

BRANCH A - If DESCRIBES PROJECT:
  → "Tell me more - what was your role?"
  → "What technologies/methods?"
  → "What problem were you solving?"
  → "What was the impact?"
  → CHECK: "Does this address {gap_area}?"
  → CAPTURE: Create bullet if substantive

BRANCH B - If MENTIONS MULTIPLE:
  → "Let's explore each. Starting with {first}..."
  → Go through systematically
  → Prioritize by gap relevance
  → CAPTURE: Multiple bullets if relevant

BRANCH C - If "NOTHING NEW":
  → "What about small improvements, process changes, learning?"
  → "New tools or technologies?"
  → "Mentoring, teaching, knowledge sharing?"
  → "Anything that might seem too small?"
  → CAPTURE: Even small items can fill gaps
```

## A real example conversation

The following is a complete discovery flow from the skill's source material, showing how a CI/CD gap is explored in practice:

```
SKILL: "I see the job requires CI/CD experience. Have you worked with CI/CD pipelines?"

USER: "Yes, I set up GitHub Actions for my side project."

SKILL: "Tell me more about that - what does the pipeline do?"

USER: "It runs tests and deploys to cloud when I push code."

SKILL: "What testing framework do you use?"

USER: "pytest for my Python code."

SKILL: "Excellent. What's deployed - is this a production app?"

USER: "Yeah, it's a tool used by 3 nonprofits right now."

SKILL: "That's substantial! Have you dealt with any flaky tests or reliability issues?"

USER: "Actually yes, I had to add retries for some API-dependent tests."

SKILL: "Perfect - that shows practical troubleshooting. Any metrics on build time
      or deployment frequency?"

USER: "Deploys take about 3 minutes, and I deploy several times a week."

[CAPTURED: Complete picture - hands-on CI/CD, pytest, flaky test handling,
production deployment. Directly fills gap with concrete details.]
```

In seven exchanges, what started as a side project becomes a substantive, evidence-rich entry: production deployment, real users, proven reliability work, and quantifiable deployment cadence. None of that would have appeared in a static checklist.

## Key principles

The discovery conversation is guided by five principles drawn from the skill's design:

**1. Start broad, go narrow.** The initial question is always open-ended. Follow-ups drill into specifics only after you've framed the territory. The skill never asks about details you've already covered.

**2. Listen and branch dynamically.** A promising answer gets explored deeper. A "no" answer triggers an adjacent probe or a graceful move to the next gap. An unclear answer gets rephrased, not repeated.

**3. Adapt to communication style.** If you give verbose answers, the skill helps you find the key takeaway. If you're terse, it offers concrete scenarios ("Was it more like X or Y?"). If you seem uncertain, it validates and provides prompts before pressing further.

**4. Recognize when to move on.** After two or three attempts with no useful signal, the skill moves on. It does not exhaust you trying to surface content that genuinely doesn't exist. Some gaps are real — they'll be flagged for the cover letter.

**5. Cross-reference during discovery.** The skill actively connects threads: "Earlier you mentioned X — does that relate here too?" or "This sounds similar to Y — are they connected?" It builds associations you might not have seen yourself.

## When this phase is skipped

Experience Discovery is **optional**. After the Phase 2 template checkpoint, the skill identifies the number and severity of gaps in your current library and offers the discovery session. You can decline if:

- Your library already covers the role well
- You're confident the gaps are real and prefer to address them in a cover letter
- Time is a constraint and you'd rather proceed directly to content matching

A good signal that discovery can be skipped: if your initial library yields an overall match confidence above roughly **75%** across the template slots, the library is likely sufficient and the session would surface only marginal additional content.

If you skip discovery, any remaining gaps are handled transparently during Phase 3 Content Matching, with explicit options for each unaddressed requirement.

<Note>
Any experiences you surface during discovery are offered for permanent addition to your resume library after the final resume is approved in Phase 5. Each discovered entry is tagged with the date, target company, and target role it was first surfaced for — so it's available and contextualized in future applications. You control exactly what gets added.
</Note>
